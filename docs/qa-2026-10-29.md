# Visual and VoiceOver review

The October 28–29 pass continued from the Claude session notes, using the local VoiceOver CLI and a separate offline QA app.

## Changes verified

- Reply tables now use native text-table cells. Columns stay aligned and wrap independently. Header text is distinct from body text.
- Table rows retain their accessibility elements while growing, and links inside rows are exposed as links.
- The composer placeholder no longer adds a plain-text VoiceOver stop after the editable field. The field keeps its explicit label and the visible placeholder keeps its contrast.
- The previously unfinished CLI exit fix reports a stopped process even when a child holds its output open.
- `Scripts/qa.sh` provides an isolated app with bundled offline scenarios. Its launch environment selects the fixture even when opened directly.

## Live VoiceOver evidence from October 28

The recorded cursor and reported speech confirmed heading levels, paragraph order, list entry and exit, list links, code-block naming, quote naming, all four table rows, and the final paragraph. Code Blocks, Heading, Link and Marked Messages rotor selections moved to their targets. The code rotor remained responsive at its end.

During a streaming reply the heading retained the same accessibility element across 28 polls over nine seconds. VoiceOver's cursor was still on that heading afterwards.

The permission sheet exposed its heading, command, Deny and Allow Once. Return left it open. Deny closed it and VoiceOver returned to the named composer. The CLI-exit scenario produced the reported phrase “Claude stopped running. Your next message starts it again.”

## Visual checks

Reviewed native component renders in light and dark appearances, at 420- and 720-point widths and at standard and doubled reply text size. Table contents wrapped within their columns without overlapping. Inspected the live dark permission and question sheets too.

Local captures and the October 28 VoiceOver JSON are in `build/qa-oct28/`. These are build artifacts and are not committed.

## October 29 follow-up

The final full `swift test` run passed: 667 tests across the three test targets (12, 297 and 358). `Scripts/bundle.sh` then rebuilt and signed `build/ClaudeNative.app` successfully.

The latest QA app exposed Swift and Apple as separate links inside their table rows. The question sheet exposed named radio buttons and checkboxes, kept Send Answers disabled until both questions had answers, and returned to the composer after submission.

Reported speech is text from VoiceOver, not an audio recording. This pass does not establish pronunciation, volume or clipping. It does not replace the release checklist for real sign-in, saved-session persistence, actual tool execution or every long-conversation rotor case.

## Latest Message overlay follow-up

The floating button was positioned at the upper left and its title was clipped. A hosted regression test reproduced a 290-point horizontal displacement, an incorrect bottom inset and a width 15 points below its intrinsic size. The scroll view now places the measured button after its own layout instead of constraining the overlay through its tiling system.

The test passes after resizing to 420, 700 and 1000 points. All 16 related navigation, scroll-following and transcript-accessibility tests pass. In the live offline QA window the button appeared at the bottom center with its complete title; pressing it moved to the latest reply, focused that reply and removed the button from the accessibility tree. This follow-up used screenshots and accessibility inspection, not live VoiceOver speech.

## File-search selection follow-up

Return in the Files filter used a selection or match from the previous query while the new search was pending. A selected URL could also remain after it left the results. The new selection tests reproduced both problems, including a folder change with an unchanged query.

The filter now hides old results while searching, clears its selection on a query or folder change, and accepts Return or Down only for the current results. A selection must belong to those results; otherwise Return chooses the current first match.

All 10 file-search and file-tree tests pass. In the offline app, a keyboard-only check changed an alpha search to beta and immediately pressed Return: Files stayed open. Once beta appeared, Return opened `beta-qa.txt`. The initial mouse-driven probe also activated a row while selecting it, so it is not evidence of the original keyboard defect. This follow-up does not establish live VoiceOver speech behavior.

## Toolbar title follow-up

A long title made the native heading component request 2,045 points of width in the regression test, leaving little room for toolbar controls. Its visible text now takes at most half a standard conversation line, with the limit derived from the system body font. The full heading name and folder remain exposed through accessibility, and the tooltip includes both lines.

The new test failed before the width limit and passes with it. All nine related toolbar, menu and composer-scale tests pass. A rendered component preview confirmed tail truncation and the retained menu caret. This check verifies the component layout and accessibility tree, not live VoiceOver speech for a long title.

## Image-only queued messages

Queued images without message text exposed identical “Edit queued message:” and “Remove queued message:” controls with nothing after the colon. Those controls now quote attachment filenames. The collapsed preview and expanded row also say “1 attached image” rather than “1 attached images” or the generic “Image message”.

The regression test failed on all four names for two queued images and on the singular preview. It now passes and confirms that removing `screenshot.png` leaves `diagram.png` queued. All 19 queue model and view tests passed; the two view tests passed again with the removal assertion included.

A live attempt reached the Add menu under VoiceOver but did not reach the image picker through automation. The queued-image labels were verified in the hosted accessibility tree, not as live VoiceOver speech. No acoustic claim is made.

## Search-picker scrolling

Command-K could keep the list scrolled far down after a query changed, although its first result was highlighted again. That left Return's target off screen. The regression test reproduced a 1,000-point scroll offset after typing a query matching the same sessions.

The slash-command and file-mention list components reproduced the same issue with an unchanged highlight and matching rows. All three now scroll to their first result when their query changes. The composer passes its query into each picker explicitly.

All 38 related picker, keyboard and search tests pass. The Command-K test types through the real field editor, confirms the first result is visible and typing focus is retained, then sends Return and confirms that session is opened. These are hosted native-view and keyboard checks; this follow-up does not establish live VoiceOver speech.

The final full suite passes with 676 tests (12 highlighting, 306 app, 358 core). The keyboard test keeps its interaction synchronous on the main actor: an asynchronous pause allowed another hosted suite to take the shared field editor during the first full run.

## Palette announcement follow-up

In Command-K, moving down promptly announced the second session, but the pending search task then announced the first session. The regression test captured those two conflicting requests in order. The pending summary now cancels when a session is explicitly highlighted, as the command picker already does.

All 33 related palette, slash-picker and search tests pass. The eight palette tests passed again with an additional check that typing a new query restores the count announcement. A separate check confirms that leaving the selection alone still announces the initial count. This verifies announcement requests and their cancellation in hosted tests, not live VoiceOver speech.

## File mentions after a folder change

The composer's file lookup was keyed only by the text after `@`. Changing its folder with that text unchanged left the previous folder's files visible and selectable. The hosted regression reproduced Return completing `qa-beta.txt` from the old folder. Results now carry both the folder and query; changing either hides the old results, cancels the old lookup and resets the highlight.

All 24 related picker and file-mention tests pass. The new regression covers both bare `@` and a typed query, checks that outdated rows disappear, and confirms Return completes the new folder's file without sending. In the running offline app, switching folders through the system chooser cleared the draft; typing `@` then listed only `gamma-qa.txt`, and Return completed it without sending. The unchanged-draft case was verified in the hosted composer, not through that app-level folder switch. A screenshot confirmed the new row and selected styling.

Live VoiceOver scripting remained attached to an unrelated “OK default button” after raising the QA window and synchronizing focus. That attempt is not a VoiceOver pass. No VoiceOver preferences were changed, and the original Claude desktop app was restored to the foreground. Both the offline QA copy and the regular app bundle were rebuilt.
